# パーティー共有用の試験的な中継プログラム

この中継プログラムは、招待コードを知る参加者の自己申告名、職業、DPS、ダメージ集計値、監視状態を同じ部屋に転送します。VRChat のログ本文は読み込みません。ユーザーが明示的に接続するまでは何も送信せず、中継先も自動で用意されません。この実装は独自のもので、他のパーティートラッカーとの互換性はありません。

中継プログラムは参加者のデータをメモリだけで保持し、退出すると削除します。ただし通信相手である中継先の運営者はデータや接続元 IP アドレスを見ることができ、ホスティングサービス側のアクセスログが残る場合があります。暗号化はクライアントと中継先の間で行われ、エンドツーエンド暗号化ではありません。名前は本人確認されず、データを偽装することも可能です。

## ローカルでの確認

Python 3.11 以上を用意し、このリポジトリのルートで次のコマンドを実行します。ここでは WebSocket は自身の PC のループバックにのみ公開されます。

```sh
python -m pip install --only-binary=:all: -r relay/requirements.txt
python -m relay.party_relay --host 127.0.0.1 --port 8765
```

アプリ側で `ws://127.0.0.1:8765` を指定して招待コードを作成します。別の PC やインターネット上からはこのアドレスに接続できません。

## ネットワークで使う場合

検証済みの中継先を別途用意し、クライアントからは証明書検証が有効な `wss://` を使ってください。直接 TLS を終端する場合は、非ループバックの待ち受けに `--cert` と `--key` の両方が必要です。`--behind-tls-proxy` は、外部からの接続を信頼できる TLS プロキシ経由に限定し、平文の内部ポートへ直接接続できない環境専用です。これらの条件が満たされない場合、このオプションは使わないでください。

招待コードには部屋の秘密情報が含まれます。知っている人は参加できるため、信頼できるメンバーだけに共有し、不要になったら新しいコードを作り直してください。人数は部屋ごとに最大 12 人です。同じ VRChat インスタンスの自動検出や、メンバーの本人確認はありません。

公開用の中継サーバーはまだ稼働しておらず、料金・運用・外部からの接続試験も未確認です。実利用やリリース前には、管理者が設定と安全性を確認してください。

## Render の設定例（未デプロイ・未試験）

ルートの `render.yaml` は、任意で Render の Free web service を使うための設定例です。ファイルを追加するだけではサービスは作成されません。デプロイには別途 Render のアカウントと設定が必要です。自動デプロイは無効で、サービス作成後に管理者が安全性を検証する必要があります。Render が外部 TLS を終端する想定のため、別のサービスで同じプロキシ設定を無条件に使わないでください。

Free には利用上限があり、一定時間通信がないと停止し、再開に時間がかかります。使用量の超過時にはサービス停止や、支払い方法が登録されている場合の追加請求が発生することがあります。実際に作成する前に、最新の [Render の無料プランの条件](https://render.com/docs/free) を確認してください。
